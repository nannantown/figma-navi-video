> **オーナー決定（2026-10-22）**: 「なんかAI教育系にしたい、AIを使いこなしたい人への教育どうが」
>
> - 見る人 = **仕事で AI を使いたい初心者**（ChatGPT などを触り始めた会社員）。見たその日に真似できる使い方のコツを**毎朝 1 つ**
> - **YouTube も Instagram も切り替える**（ニュース型はやめる）。YouTube のチャンネル名・説明文は AI 全般なので変えない
> - Instagram は作り直す新しいアカウント **@ai_ground_school**（表示名「AI Ground｜仕事で使えるAI 毎朝1分」。2026-10-22 夕方のオーナー決定で @ai_ground_daily から変更）で出す。作り直しが済むまでは今の Instagram の設定のまま

> - AI Trend Daily（GitHub トレンド）と重ねない。**GitHub のリポジトリは紹介しない**
> - 特定の有料プランを勧めない。誇大な言い方（「誰でも月◯万」「最強」「◯倍速」など）をしない
> - 見せ方は今の型を引き継ぐ: 上半分の図解・下のメイと吹き出し・円の概算（**2026-10-23 から参考リール型の手順動画に切り替え = §6**。4 枚のカードは `"lessonLook": "cards"` で戻せる）
> - 朝ルーチン: [routine-prompt-lesson.md](routine-prompt-lesson.md)。見本: [lesson-preview/](lesson-preview/README.md)

## 1. 1 本の構成（4 枚・1 分以内）

| 枚 | 役割 | 画面の上半分（図） | 下のメイの吹き出し |
|---|---|---|---|
| 1 | **困りごと** — 見る人の「あるある」 | `compare`（前/後）・`steps`・`flow` のどれか | 困っている場面を 1〜2 文で |
| 2 | **そのまま使える頼み方** | **`prompt`**: AI の入力欄の形で、コピーして使える頼み方の文（12〜70 字）が 1 字ずつ打ち込まれ、送信ボタンが光る | どこを自分の仕事に書きかえるか |
| 3 | **答えの例** | **`answer`**: AI の答えの吹き出し（8〜60 字の一例） | どんな形で返ってくるか |
| 4 | **ひとこと注意** | `steps`（やる順）か `compare` | 確かめること・入れてはいけない情報 |

- オープニング: 大きな文字「LESSON」、ラベル「今日のAI仕事術」、見出し（その日の 1 本の名前）
- エンディング: 「毎朝ひとつ、仕事で使える / AI の頼み方」、ナレーション「今日の AI 仕事術でした。保存とフォローで、毎朝ひとつずつ。」（**CTA は保存とフォロー**）
- キャプション: タイトル【AI仕事術】見出し｜日付 #Shorts。本文の**いちばん上に「▼ そのまま使える頼み方（コピーして使えます）」と頼み方の文**（Instagram の「続きを読む」の前に見え、そのままコピーできる = 保存の理由になる）→ スライドの要点 → 注記「※AI の答えは一例で、聞くたびに少し変わります。数字・名前・日付は元の資料で確かめてください。会社の決まりで使えない情報は入れないでください。円の金額は概算です。」→（出典があれば出典）→ 締め → ハッシュタグ（IG `#AI活用 #ChatGPT #生成AI #仕事術 #業務効率化`、YT `#AI活用 #ChatGPT #仕事術 #Shorts`）
- メイ: リポジトリ変数 `MAY_CHARACTER` が `on` なら news / Jev と同じく出る

## 2. ネタの柱（8 本を順に回す）

`pillar` の値と `topic_key` の頭（`mail-polite-decline` など）。同じ柱が 2 日続くと検証が警告する。

| `pillar` | 柱 | 例 |
|---|---|---|
| `ask` | 頼み方の型 | 誰に・何を・どんな形で / 先に質問させる / 見本を見せる |
| `summary` | 要約 | 3 行で / 立場を決めて絞る / 新旧の違いだけ |
| `mail` | メール | 断り / やわらかく直す / 件名 |
| `sheet` | 表計算 | 式を日本語で聞く / 表記をそろえる / 式の意味を聞く |
| `slides` | 資料づくり | 目次から / 1 枚 1 メッセージ |
| `research` | 調べもの | 知らない言葉を例つきで / 比べる点を表に |
| `check` | 確かめ方 | 弱いところを聞き返す / 根拠の資料名を聞く / 誤字を見つける |
| `meeting` | 会議・議事録 | メモを 3 つに分ける / 30 分の議題 |

**選ばないもの**: GitHub・リポジトリ・プログラミングの話（AI Trend Daily と重なる。初心者向けでもない）、特定の有料プラン・課金の話、「稼げる」「副業」の話、特定の AI だけにある機能（どの AI でもそのまま使える頼み方にする。ChatGPT・Gemini・Claude・Copilot のどれに貼っても通じる文）、ニュース（新機能の発表など。この型は「使い方」）、契約書・法務・税・医療・人事評価・顧客データの分析、AI の Web 検索・ファイル添付・最新情報に頼る頼み方（AI や設定によって使えない・答えが変わる）。

### 常備ネタ帳 `data/ai-lesson-stock.json`

台帳と同じ形の回（`date`・`genre`・`trial`・`kind` を除く）を並べたもの。2026-10-22 時点で 21 本（3 週間分、8 本の柱を順に回す並び）。

- 朝ルーチンは、ふだんは `node scripts/jev.mjs next` の `stockNext`（まだ出していない最初の 1 本。前の日と柱が違うものが先）をそのまま今日の回にする
- **今日の回が main に無い・検証に通らない朝は、08:15 の動画生成（`scripts/generate-data.mjs`）がネタ帳の `stockNext` を自動で出す**（Actions に黄色い注記「予備のレッスンで投稿」）。ルーチンの原稿 PR が merge されないまま止まる日が多いので（[routine-merge-miss.md](routine-merge-miss.md)）、教育の型では空白日を作らない。予備で出した回は投稿の記録（`performance-history.json` の `jev.fallback: true`・`jev.topicKey`・`jev.prompt`・`jev.pillar`）に残り、同じ回・同じ文例は二度と出ない（この記録は台帳に無い唯一の記録なので、投稿の記録の 90 日の刈り込みでも消さない）
- **その日すでに予備で出していたら、その日はその回だけ**: 同じ日の再実行・Instagram のやり直しは同じ予備の回を作り直す。あとから朝ルーチンの別の回が main に届いても使わず、検証がその回を `already went out from the stock` で止める（`deliver-jev` も merge しない）。その PR は閉じる。前の日の Instagram のやり直しでは、この例外は使わない（`assert-data-date.mjs` は今日の日付だけ認める）
- 残りが 7 本以下になったら、朝ルーチンはネタ帳から取らずに**新しい回を自分で書く**（予備を残すため）。残りが 10 本を切ったら最終レポートに「ネタ帳の補充が必要」と書く。補充はネタ帳に足す PR（朝ルーチンの PR には混ぜない）で、`npm run validate:stock` が通ること
- ネタ帳に足すとき・直すときは `npm run validate:stock`（全部の回を 1 日 1 本ずつ出した想定で検証。ネタ帳の中の重複も見つかる）

### 検証（`node scripts/jev.mjs validate`。NG が 1 つでもあれば main に入れない）

| 何を | ルール |
|---|---|
| `date` / `genre` / `trial` / `kind` | 今日（JST）/ `"ai-lesson"` / `4` / `"lesson"`。日付は昇順で 1 日 1 回。やり直し（`redo_of`）は無い |
| `pillar` / `topic_key` | 上の 8 つのどれか / 英小文字とハイフン、柱の名前で始める（`mail-…`）。**シリーズ全体で 1 回だけ**（投稿の記録にあるキーも不可） |
| 文字数 | `topic` 4〜40 / `headline` 6〜24（過去回と同じ見出しは不可）/ `hook` 8〜40 / スライド `heading` 4〜18・`body` 8〜64・`narration` 30〜95（合計 300 字以内 = 60 秒未満） |
| スライド | **ちょうど 4 枚**。2 枚目の図は `prompt`、3 枚目は `answer`（どちらも `items` 1 つ・`label` だけ。`prompt` 12〜70 字、`answer` 8〜60 字）。1・4 枚目は `steps` / `flow` / `compare`（図が無い・壊れているときは警告だけで、見出し＋本文の表示になる） |
| **同じ文例を 2 回出さない** | 2 枚目の頼み方の文を、台帳のこれまでの回と投稿の記録（予備で出した回も）の全部と比べる。句読点・空白を除き、漢数字を数字にそろえた 2 文字ずつの重なり（Dice 係数）が **0.55 以上なら同じ文例として NG**（言い回しを少し変えただけのものも止まる。ネタ帳の 21 本どうしは最大 0.35）。**限界**: 文をほとんど書きかえた同じ中身（「この文章を三行でまとめて」と「次の文章を、上司が30秒で読めるように3行で要約」は 0.35 前後）は機械では止まらない。朝ルーチンはこれまでの回の頼み方の文を読み、同じ中身を避ける（手順書 1・4）。もう出た文例と似ているネタ帳の回は `stockNext` に出てこない |
| 有料プラン | 「有料プラン」「有料版」「課金」「月額」「サブスク」「ChatGPT Plus」「〇〇 Pro / Max / Team / Advanced …」などは NG（画面・ナレーション・見出し・図の列の見出し・出典の媒体名のすべて） |
| 誇大な言い方 | 「誰でも簡単に / 誰でも月◯万 / 誰でもできる」「月◯万・月収◯万」「お金を稼ぐ・稼げる」「儲かる」「副業」「楽して稼ぐ」「爆速」「神ツール」「最強」「革命」「激変」「魔法の」「一瞬で」「裏技」「知らないと損」「◯倍速」などは NG（「誰でも分かる言葉で」「毎日楽しく」「時間を稼ぐ」は通る） |
| GitHub | 「GitHub」「リポジトリ」は NG（出典の URL・媒体名も。AI Trend Daily と重ねない） |
| 主張・金額 | news / Jev と同じ（性能の主張は名指し、ドル表記は NG・円の概算） |
| **社外秘の注意** | 頼み方の文・2 枚目の本文・2 枚目のナレーションのどこかに「貼」「下記」「以下」「次の」「上記」「つぎの」「この〜」（このデータ・この内容・この報告書など何でも。「かっこの」「どこの」のような言葉の途中は除く。2 枚目の本文・ナレーションの「この一文」「この頼み方」「このように」「このまま」など頼み方そのものを指す言葉は数えないが、頼み方の文の中では数える）「ここの」「これを」「こちらの」「下の」「上の」「添付」「届いた」「メモを」「議事録」がある回（社内の文章・表・メールを貼る回。広めに拾う）は、2 枚目のナレーションか 4 枚目の画面・音声（見出し・ナレーション・図の文字。図のある 4 枚目の本文はキャプションにしか出ないので数えない）に 社外秘 / 個人情報 / 個人名 / 人の名前 / 仮名 / 会社のルール / 会社の決まり のどれかが無ければ NG（「社外秘・人の名前・社名は消すか A社・Bさんのような仮名にしてから貼る」「会社のルールで AI に入れてよいかを先に確かめる」） |
| 表計算の関数 | 表計算の柱で関数の名前（SUMIFS・IF など、英大文字 2 字以上。AI は除く）を出す回は、提供元の公式のヘルプ（例: Microsoft サポートの関数のページ、`official: true`）が出典に無ければ NG |
| 出典 | 0〜4 件（`role` は `reference` だけ）。AI の機能・表計算の関数の説明に、提供元の公式のページ（`official: true`）を使ったときに書く。提供元以外の解説を添えたら `official: false`。`research.checked` は任意 |
| 文字のフィールド | URL・@・#・改行・`<` `>`・ドル表記を入れない |

## 6. 参考リール型の見た目（`lessonLook: "reel"`。2026-10-23 オーナー決定）

> オーナーの言葉「1回あのキャンバスに出してる案でやってみよう。」（sns-hub の Canvas「AI Ground 新しい見た目の見本（参考リール型）」の作りを本番に。続けるかは §1 と同じく保存数とフォロワー増を 2 週間ごとに見て決める）

`data/content-format.json` の `"lessonLook"` が `"reel"` の間、毎朝の動画は 4 枚のカードではなく**手順型**で出る（`src/compositions/LessonReel.tsx`、作り方は `scripts/reel.mjs`）。

- 画面: 白に近い暖かい地にオレンジ 1 色・ゴシックだけ。上に手順の数だけ分けた進み具合のバー、左上に「Step N」と見出し（1 語だけオレンジ）、中央に**自前の簡略化した AI の窓**（名前は「AIチャット」。本物の会社の画面は写さない）、下に今言っている語の字幕（1 語だけオレンジ）。見出し 64px ÷ 字幕 48px = 1.33
- 流れ: つかみ（`reel.title` と「N ステップ」）→ ステップ 1〜N（窓の中で 1 つずつ: 開く・貼る・打つ・送る・確かめる）→ まとめ（手順の一覧、「これで完了です。」）→ 保存の誘い（「保存して、見返す」・しおり・「フォローすると、ほかの仕事術も届きます」）
- 声: Edge TTS `ja-JP-NanamiNeural` +12%（58 秒を超える日だけ +20% → +28%）。場面ごとに声を作り、語の時刻に字幕・打鍵・カーソルを合わせる。書き出した mp4 を ffprobe で測り、59 秒を超えたら使わない
- **作れなかった日**（声が取れない・書き出しが失敗・59 秒を超える）は、同じ回を 4 枚のカードで出す（Actions に黄色い注記「参考リール型で作れなかった」）。投稿の記録 `performance-history.json` の `look` に、その日にどちらで出たか（`reel` / `cards`）が残る
- 今日の回の `reel` が無い・検査に通らない日は、ほかの NG と同じくネタ帳の回（`reel` つき）が出る。ネタ帳にも使える回が無く、NG が `reel` だけなら、今日の回を 4 枚のカードで出す（注記「手順型の台本が検査に通らない」）。`"lessonLook"` の書き間違いは 4 枚のカード扱い（注記「lessonLook の書き間違い」）
- 時間の上限: 声 4 分・書き出し 8 分。超えたら 4 枚のカードに切り替える（ジョブ全体は 20 分）
- Instagram の表紙はつかみの最後のコマ（題名と N 本のバー）。メイは出ない
- キャプションは今までどおり（いちばん上にコピーできる頼み方の文）

### 台本 `reel`（台帳とネタ帳の各回に足す。4 枚の `slides` も今までどおり書く = 中身・キャプション・戻すとき用）

```json
"reel": {
  "title": "議事録は、AIで",
  "hook": "議事録づくりは、AIに任せましょう。5つの手順です。",
  "file": "会議メモ.txt",
  "answer": [
    { "head": "決まったこと", "lines": ["申請フォームを11月から使う"] },
    { "head": "やること", "lines": ["Aさん：説明資料（金曜まで）", "Bさん：社内に案内を出す"] },
    { "head": "保留", "lines": ["予算の上限"] }
  ],
  "steps": [
    { "action": "open", "heading": ["AIを", "開く", ""], "narration": "ステップ1。ふだん使っているAIで、新しいチャットを開きます。" },
    { "action": "paste", "heading": ["会議のメモを", "貼る", ""], "narration": "ステップ2。人の名前や社名を仮名にしてから、会議のメモを貼ります。", "accents": ["メモ", "仮名"] },
    { "action": "type", "heading": ["形を", "指定", "する"], "narration": "ステップ3。決まったこと、やること、保留の3つに分けて、と書きます。" },
    { "action": "send", "heading": ["送って", "待つ", ""], "narration": "ステップ4。送信すると、3つに分かれた議事録ができます。" },
    { "action": "check", "focus": ["やること", "保留"], "heading": ["自分で", "確かめる", ""], "narration": "ステップ5。担当と期限が合っているか確かめ、仮名を元に戻します。" }
  ]
}
```

| 何を | 決まり（`node scripts/jev.mjs validate` が見る） |
|---|---|
| `steps` | **3〜5 個**。`action` は `open`（新しいチャットを開く）/ `paste`（ファイルの札を入力欄へ）/ `type`（頼み方の文を 1 字ずつ打つ）/ `send`（送信 → 答えが 1 行ずつ）/ `check`（答えの見出しを囲んでチェック）。**この順で 1 回ずつ**、`type` と `send` は必ず入れる。打たれる文は 2 枚目の頼み方の文（`slides[1]`）そのもの |
| `heading` | `["前", "オレンジの語", "後"]`。3 つ合わせて 2〜12 字（1 行に収まる） |
| `narration` | 14〜50 字、**「ステップN。」で始める**。打つ場面は「…、と書きます。」、送る場面は「送信すると、…」のように、画面で起きることをそのまま言う |
| `accents` | 任意。字幕でオレンジにする語（0〜4 個、ナレーションに含まれる語）。無ければ見出しのオレンジの語 |
| `title` / `hook` | 題名 2〜11 字（2 行目は自動で「N ステップ」）/ つかみの声 10〜40 字、**「Nつ」を含める**（バーがその語で出る） |
| `answer` | 答えの例。1〜3 つの見出し（1〜10 字）と行（1 行 2〜20 字）、見出しと行を合わせて 7 行まで。作り話の事実を入れない（仮名・一例） |
| `file` | `paste` があるときだけ。ファイルの名前 3〜14 字（`会議メモ.txt` など） |
| `note` / `done`（paste） | 任意。貼る前に札に付く注意（既定「名前は仮名に（Aさん・B社）」4〜16 字）と、貼ったあと（既定「仮名にしてある」3〜8 字）。`""` で出さない |
| `note`（check）/ `focus` | 任意。答えに付く札（既定は `paste` があれば「仮名 → 元の名前に」、`""` で出さない）/ 囲む見出し 1〜2 個（既定は最初の 2 つ） |
| **社外秘の注意** | 頼み方の文が貼る形（§3 の社外秘の注意と同じ言葉を拾う）なら **`paste` の手順が必須**。`paste` がある回は、貼る札・ナレーション・確かめる札のどこかに 社外秘 / 個人情報 / 個人名 / 人の名前 / 仮名 / 会社のルール / 会社の決まり が要る（既定の札は「仮名」を含む） |
| 長さ | 声に出す字数（つかみ + 手順 + 決まった文 2 つ）で 250 字まで（≒ 55 秒）。有料プラン・誇大表現・GitHub・ドル表記・改行は §3 と同じく NG |
