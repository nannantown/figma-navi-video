## なぜこのジャンルか（仮説）

1. **型に再現性があるかを確かめる**: AI Trend Daily の IG は「毎日の TOP5 カタログ」型で、09-01〜09-14 に views 中央値 907・保存 95 を出している。3 リポのうち届いているのはこのアカウントだけ。同じ型を別のテーマで回して、効いているのが型なのかテーマなのかを切り分ける。
2. **客層をずらす**: AI Trend Daily は GitHub を扱う開発者向け（技術の目利き）。こちらは Product Hunt の「すぐ使えるツール」を扱い、非エンジニアの会社員・クリエイター向けにする。どちらも AI に関心がある層だが、見るもの（リポジトリか、使えるサービスか）が違う。
3. **保存されやすい中身にする**: 「名前・何ができる・誰向け・料金・URL」は、あとで試すためのリストとして保存する理由になる。デザインニュースは 80 本で保存 0 だった。

## フォーマット仕様

- **新作だけを扱う**: Product Hunt で公開（ローンチ）されたのが「朝ルーチン時点の太平洋時間の前日 0:00 以降」のツールだけ（必ず直近 48 時間以内）。フィードには公開日時が無い（`published` は投稿を作った日時で、公開の数週間〜数か月前のこともある）ため、次のどちらかで確かめる: ①投稿の作成日時が範囲内（公開は作成より後なので範囲内）、②範囲の開始より後に取ったスナップショットには載っておらず、その後に載った（スナップショットの `listedAfter`）。②は「範囲の開始の 3 時間前まで」を証拠として認める（Product Hunt がその日の分を並べるのは太平洋時間 0:01 で、0:00 ちょうどの取得は定時実行では保証できないため。14:43 JST の取得がこの証拠になる）。範囲は `node scripts/fresh-since.mjs` で確認でき、検証（`validate-enriched.mjs`）が範囲外を弾く
  - ②が付くのは、スナップショットがすでに知っている投稿**より上に**新しく出た投稿だけ（フィードは新しい公開日から並ぶので、前回の取得の後に公開された投稿は必ず上に出る）。下のほうに初めて出た投稿（古い日の投稿が繰り上がって見えたものなど）には付けない
  - ②で確かめられるのは、主に朝ルーチンの前日（太平洋時間）に公開された分。その前の日に公開された分は①（作成日時）で確かめられたものだけが候補になる。そのため週明けなどは候補が少ない日がある
- **本数**: **2〜5 本**（N選）。使える新作が 5 本以上ある日は 5 本にする。使える新作が 2 本に満たない日は**投稿を休止**する（休止の形のデータを書き、パイプラインは動画を作らない）
- **休止は黙って起きない**: 当日向けのスナップショットで新作の AI ツールが 2 本以上あるのに休止すると検証エラー（パイプライン失敗で通知）。選定ルールや NG パターンで外した候補は、理由（`recent` 直近 30 日に紹介済み / `ng` NG パターン / `no-site` 公式サイトなし / `invite-only` 招待制 / `not-ai` AI カテゴリ外のキーワード一致）と一緒に `skip.excluded` に書けば数に入れない。休止した日は GitHub に警告と要約を出し、performance-history.json に休止日として記録する（中央値・合計には入れない）
- **1 本に載せる情報**: 名前 / 一言（何ができる）/ 誰向け / 料金（無料・無料プランあり・トライアル・有料）/ 公式サイト（ドメインを表示）。ロゴかスクリーンショットが取れれば 1 枚入れる（取れなければ文字だけ）
- **順位は名乗らない**: 並びはルーチンのおすすめ順で、Product Hunt の順位や票数ではない。カードの番号は「1/5」表記、カードの出典行は「Product Hunt 新着」（フィードには公開日が無いので日付は出さない）。画面・キャプション・ナレーション・ツール名で順位を思わせる言葉（TOP・トップ・ランキング・◯位・一位・首位・上位N・ベストN・No.N・ナンバーワン。全角・半角カナ・英語表記・記号をはさんだ書き方も）を使わない（検証エラー）。票数・受賞（Product of the Day など）・「トップに輝く」「一番人気」「Product Hunt で話題」のような人気の主張も同じ。ツール名そのものがこれに当たるツールは、名前を変えずに除外する。ツールは当日向けスナップショットに載っている新作に限り、名前はスナップショットの名前のまま（言い換えない）
- **照合はルーチンが見たデータで**: 動画生成（08:15）は、ルーチンの原稿をマージしたコミットに入っている版のスナップショットで照合する。その後に届いた更新では照合しないので、後から候補が増えた・消えたことで投稿が失敗することはない
- **ナレーション**: AI Trend Daily の 2 文構成を踏襲する。フック 1 文 + 要点 1 文、40〜58 字、です・ます調。順位・票数・人気には触れない（フィードに無い情報で、名乗らない決定）。オープニングで本数を言うときは、その日の本数と合わせる（検証エラー）
- **動画の構成**: オープニング（日付・「新作AIツール N選」・「Product Hunt の新着から厳選」）→ ツールのカード → エンディング（保存を促す）。**60 秒未満**。長くなりそうなときは pipeline が読み上げ速度を自動で上げる
- **出典の表記**: 動画とキャプションに Product Hunt を明記する。YouTube 概要欄には各ツールの Product Hunt ページの URL を文字で載せ、「出典: Product Hunt」と書く（Shorts の概要欄の URL はクリックできない仕様。YouTube ヘルプ https://support.google.com/youtube/answer/13748639 、2026-09-16 確認）。Instagram もキャプションのリンクは効かないので「出典: Product Hunt」の表記
- **自動マージの安全策**: ルーチンの原稿は人の確認なしで公開されるため、文字のフィールドに URL・ドメイン名（全角・句点・`[.]` や `dot` の書き換えも。`Next.js` のような技術名は可。ツール名は公式サイトと同じドメインも可）・@メンション・#ハッシュタグ・改行・制御文字・見えない文字・コメントや DM を促す文（「『AI』とコメントして」など）・「前の指示を無視して」のような指示文があると検証で止める（全角・半角の違いをそろえてから判定）。公式サイトの URL は 200 字まで、クエリ（`?ref=…`）・ポート・IP アドレス・短縮 URL・チャットの招待・フォーム・リンクまとめのプロフィールページは不可。30 日以内に紹介したツールも検証で止まる。`ranking` モードは検証で無効（参考用のドライランだけ `PH_ALLOW_RANKING=1` で通す）。画像の取得は公開アドレスの https だけ、時間にも上限（1 ツール 30 秒・全体 90 秒）がある

### 取得モード

| モード | 使うか | 並び順 | 出典表記 |
|---|---|---|---|
| `pickup` | **使う（既定・固定）**。`fetch-product-hunt.yml` は `PH_SOURCE=feed` で公式フィードだけを読む | 公式フィードの新着（新作の範囲内）から、ルーチンが「使える」順に 2〜5 本を選ぶ | 「新作AIツール N選」「Product Hunt の新着から厳選」。**投票順ではないので「TOP」「ランキング」「◯位」とは言わない** |
| `ranking` | **使わない**（2026-09-15 オーナー決定）。コードは残してあるが、ワークフローはトークンを渡さないので、Secret を登録しても切り替わらない。使うにはオーナーの判断と、`PH_SOURCE=api` とトークンをワークフローに渡す PR が必要 | （API の dailyRank 順） | （「TOP5」と総合順位） |

- **2026-09-15 オーナー決定（B）**: 公式 API は使わない。API ドキュメントに「商用目的での利用は不可。ビジネスで使う場合は hello@producthunt.com に連絡」とあるため（https://api.producthunt.com/v2/docs）。トークンの発行依頼・許可の連絡はしない。出典として動画・キャプションに Product Hunt を明記し、YouTube 概要欄に Product Hunt の URL を載せる
- 自動で取得するのは公式フィード（`https://www.producthunt.com/feed`、robots.txt で許可）だけ。サイト本体のページ（leaderboard や製品ページ）は自動で読まない。ツールの中身は各ツールの**公式サイト**で確認する
- **実測（2026-09-15 23:15 JST、公式フィード）**: AI カテゴリの 50 件は公開日ごとに新しい日から並んでいた（製品ページで確認: 1〜18 件目 = 9/15 公開、19〜23 件目 = 9/14、24 件目 = 9/13、45 件目 = 9/11）。投稿は公開の数日〜数か月前に作られることが多く（例: Voiskey は 8/31 作成・9/15 公開、is.team は 4/3 作成・9/15 公開）、作成日時だけで新作を判定すると 9/16 の動画に使える AI ツールは 3 件だった。そこでスナップショットが「掲載の初出」を引き継ぐようにした（上の「新作だけを扱う」の②）。これで前日に公開された AI ツール（この日は 18 件）が候補になり、**毎日 5 本を選べる見込み**。ただしスナップショットを引き継ぎ始めた最初の朝は②が使えず、作成日時だけで判定する
- **実測（2026-09-16 04:19・04:30 JST に 11 分あけて 2 回取得、敵対レビュー）**: 同じ公開日の中の並びは数分で入れ替わるが、公開日をまたいでは入れ替わらなかった。一般フィードの 50 件は AI カテゴリの 24 件目あたり（前日の途中）までしか届かず、それより古い AI ツールは AI カテゴリのフィードでしか見えない。これを受けて、②は「既知の投稿より上に新しく出た投稿」だけに付け、取得を「両方のフィードが 20 件以上・AI カテゴリにだけある投稿が 10 件以上」のときだけ完全とみなすようにした。フィードの取得は 1 本につき 3 回まで再試行する

## 選定ルール

1. 直近 30 日に紹介したツールは選ばない（`node scripts/pdca-summary.mjs` の出力に一覧がある。検証でもエラーになる）
2. NG パターンに当たるものは飛ばし、次の候補を繰り上げる
3. 3 本以上選ぶ日は、その過半数を非エンジニアが今日使えるものにする
4. 開発者向けは 5 本中 2 本まで（method が `dev-theme` の日は除く）
5. 新作の範囲外（公開が古い）のツールは、どれだけ良くても選ばない
6. 料金は公式サイトで確認できたものだけ `free` / `freemium` / `trial` / `paid` にする。確認できなければ `unknown`（推測しない）
7. 公式サイトの URL を記録する（Product Hunt のリダイレクト URL は使わない）

## Discovery Methods（選び方の切り口）

型は変えずに、**新作の範囲からどのツールを選ぶか**の切り口を日次 PDCA で最適化する。

| タグ | 選び方 |
|---|---|
| `rank-pure` | ランキング順そのまま（ranking モード専用。2026-09-15 以降は使わない） |
| `non-engineer` | 非エンジニアが今日使えるものを優先 |
| `free-first` | 無料・無料プランありを優先 |
| `job-theme` | 職種テーマ（営業・経理・人事・マーケなど）で揃える |
| `creator-theme` | 画像・動画・文章などクリエイター向けで揃える |
| `dev-theme` | 開発者向けで揃える（週 1 回まで） |

- **80/20**: 直近 14 日で IG views 中央値と保存の成績が良い method を 80% の日に使い（exploit）、残りの 20% で他の method を試す（explore）
- 本数が少ないうち（method ごとに n < 3）は explore を多めにしてよい
- 同じ method を 3 日連続では使わない

## NG パターン

| NG | 理由 |
|---|---|
| 暗号資産・投機・ギャンブル・アダルト系のツール | ブランドを傷つける |
| 誇大表現（「最強」「神ツール」「これ一択」「稼げる」） | 信頼を失い、保存する理由も薄れる |
| 確認していない料金や機能を言い切る | 誤情報になる。料金は公式サイトで確認できた範囲だけ書く |
| 「ランキング」「TOP」「1 位」と言う。票数・受賞・「Product Hunt で話題」などの人気を主張する | 順位ではなく、フィードに票数も無いので出典に対して不誠実（2026-09-15 オーナー決定） |
| 「『AI』とコメントして」「DM で送って」など反応を求める文 | 自動投稿で約束を守れない。スパムに見える |
| 英語のタグラインを直訳・直読みする | 視聴者は日本語話者。何が便利かを日本語で伝える |
| 60 秒を超える詰め込み | Instagram が投稿を受け付けない |
| 30 日以内に紹介したツールの再掲 | 重複して飽きられる |
| 顔や個人情報が大きく写ったスクリーンショット | 権利・プライバシーの問題 |
| 出典の記載漏れ | 信用を失う。`discovery.sources` に URL を必ず残す |

### performance-history.json の指標

| キー | 取得元 | 更新 |
|---|---|---|
| `genre` / `trial` / `tools[]` / `source` | 投稿時に `record-upload.mjs` が記録（`tools[]` は 30 日以内の重複チェックにも使う） | 投稿時 |
| `skip`（休止日だけ） | `record-upload.mjs --skip` が `{ reason, fresh_candidates, snapshot_fresh_ai }` を記録。`videoId` / `instagram` は null。中央値・合計・学習・開始日には使わない | 休止した朝 |
| `stats.views` / `likes` / `comments` | YouTube Data API v3 | `fetch-stats.mjs`（直近 14 日） |
| `instagram.mediaId` | 投稿時に `upload-instagram.mjs` → `record-upload.mjs` が記録。記録がない回は `fetch-stats.mjs` が IG の投稿一覧と JST の投稿日で突き合わせて復元する | 投稿時 / 初回取得時 |
| `instagram.views` / `reach` / `likes` / `comments` / `shares` / `saved` | Instagram Graph API `/{ig-media-id}/insights` | `fetch-stats.mjs`（直近 14 日 + 未取得の回）。最大 48 時間遅れる |

更新だけ手動で行いたいときは `gh workflow run fetch-stats.yml` を使う（動画生成・投稿はしない）。
