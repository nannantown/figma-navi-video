## なぜこのジャンルか（仮説）

1. **型に再現性があるかを確かめる**: AI Trend Daily の IG は「毎日の TOP5 カタログ」型で、09-01〜09-14 に views 中央値 907・保存 95 を出している。3 リポのうち届いているのはこのアカウントだけ。同じ型を別のテーマで回して、効いているのが型なのかテーマなのかを切り分ける。
2. **客層をずらす**: AI Trend Daily は GitHub を扱う開発者向け（技術の目利き）。こちらは Product Hunt の「すぐ使えるツール」を扱い、非エンジニアの会社員・クリエイター向けにする。どちらも AI に関心がある層だが、見るもの（リポジトリか、使えるサービスか）が違う。
3. **保存されやすい中身にする**: 「名前・何ができる・誰向け・料金・URL」は、あとで試すためのリストとして保存する理由になる。デザインニュースは 80 本で保存 0 だった。

## ペルソナ（優先順）

| 優先 | ペルソナ | 欲しいもの |
|---|---|---|
| Primary | 仕事で AI を使いたい非エンジニア（会社員・PM・マーケター・営業・バックオフィス） | 今日から使える、仕事が速くなるツール。無料で試せるか |
| Secondary | クリエイター・個人事業主・学生 | 画像・動画・文章・学習の時短ツール |
| Tertiary | エンジニア | AI Trend Daily と客層が重なるため主な対象にしない（開発者向けは 5 本中 2 本まで） |

## フォーマット仕様

- **毎日 5 本**。Product Hunt のランキング（またはトークンがない日は新着）から、AI 系または開発者向けのツールを選ぶ
- **1 本に載せる情報**: 名前 / 一言（何ができる）/ 誰向け / 料金（無料・無料プランあり・トライアル・有料）/ 公式サイト（ドメインを表示）。ロゴかスクリーンショットが取れれば 1 枚入れる（取れなければ文字だけ）
- **ナレーション**: AI Trend Daily の 2 文構成を踏襲する。フック 1 文 + 要点 1 文、40〜58 字、です・ます調。順位や票数は読み上げない（画面に出ている）
- **動画の構成**: オープニング（日付・「新作AIツール TOP5」・出典）→ ツール 5 枚 → エンディング（保存を促す）。**60 秒未満**。長くなりそうなときは pipeline が読み上げ速度を自動で上げる
- **出典の表記**: 動画・キャプション・概要欄に Product Hunt を明記する

### データの流れ

```
fetch-product-hunt.yml   18:30 JST（前夜）/ 06:30 JST（予備）
  └ data/product-hunt-daily.json   ← 公式 API（トークンがある場合）/ 公式フィード（ない場合）
朝ルーチン                07:30 JST
  └ 5 本を選び、公式サイトで確認して日本語化 → data/enriched-ai-tools.json + docs/pdca/YYYY-MM-DD.md
daily-video.yml           08:15 JST
  └ ロゴ取得 → 音声 → 動画 → YouTube Shorts / Instagram Reels に投稿 → performance-history.json に記録
```

### 取得モード

| モード | 条件 | 並び順 | 出典表記 |
|---|---|---|---|
| `ranking` | Secret `PRODUCT_HUNT_API_TOKEN` が設定済み | 米国太平洋時間の前日（集計が確定した日）の dailyRank 順。AI・開発者向けツールの上位 5 本 | 「Product Hunt M/D ランキングより」 |
| `pickup` | トークンなし（初期状態） | 公式フィードの新着から、ルーチンが「使える」順に 5 本を選ぶ | 「Product Hunt の新着から厳選」。**投票順ではないので「ランキング」「◯位」とは言わない** |

- Product Hunt API の規約には「商用目的での利用は不可。ビジネスで使う場合は hello@producthunt.com に連絡」とある（https://api.producthunt.com/v2/docs）。トークンを使うかどうかと、連絡するかどうかは**オーナーが判断する**
- サイト本体（leaderboard や製品ページ）を自動で巡回しない。サイトの規約で自動収集が禁止されているため。ツールの中身は各ツールの**公式サイト**で確認する

## 選定ルール

1. 直近 30 日に紹介したツールは選ばない（`node scripts/pdca-summary.mjs` の出力に一覧がある）
2. NG パターンに当たるものは飛ばし、次の候補を繰り上げる
3. 5 本のうち 3 本以上は、非エンジニアが今日使えるものにする
4. 開発者向けは 5 本中 2 本まで（method が `dev-theme` の日は除く）
5. 料金は公式サイトで確認できたものだけ `free` / `freemium` / `trial` / `paid` にする。確認できなければ `unknown`（推測しない）
6. 公式サイトの URL を記録する（Product Hunt のリダイレクト URL は使わない）

## Discovery Methods（選び方の切り口）

型は変えずに、**どの 5 本を選ぶか**の切り口を日次 PDCA で最適化する。

| タグ | 選び方 |
|---|---|
| `rank-pure` | ランキング順そのまま（ranking モードの基本） |
| `non-engineer` | 非エンジニアが今日使えるものを優先 |
| `free-first` | 無料・無料プランありを優先 |
| `job-theme` | 職種テーマ（営業・経理・人事・マーケなど）で揃える |
| `creator-theme` | 画像・動画・文章などクリエイター向けで揃える |
| `dev-theme` | 開発者向けで揃える（週 1 回まで） |

- **80/20**: 直近 14 日で IG views 中央値と保存の成績が良い method を 80% の日に使い（exploit）、残りの 20% で他の method を試す（explore）
- 本数が少ないうち（method ごとに n < 3）は explore を多めにしてよい
- 同じ method を 3 日連続では使わない

## NG パターン

| NG | 理由 |
|---|---|
| 暗号資産・投機・ギャンブル・アダルト系のツール | ブランドを傷つける |
| 誇大表現（「最強」「神ツール」「これ一択」「稼げる」） | 信頼を失い、保存する理由も薄れる |
| 確認していない料金や機能を言い切る | 誤情報になる。料金は公式サイトで確認できた範囲だけ書く |
| pickup モードで「ランキング」「1 位」と言う | 出典に対して不誠実 |
| 英語のタグラインを直訳・直読みする | 視聴者は日本語話者。何が便利かを日本語で伝える |
| 60 秒を超える詰め込み | Instagram が投稿を受け付けない |
| 30 日以内に紹介したツールの再掲 | 重複して飽きられる |
| 顔や個人情報が大きく写ったスクリーンショット | 権利・プライバシーの問題 |
| 出典の記載漏れ | 信用を失う。`discovery.sources` に URL を必ず残す |

| 種別 | 指標 | 取得元 |
|---|---|---|
| 判定指標 | IG views 中央値 / IG 保存合計（14 日窓） | `performance-history.json` の `instagram.views` / `instagram.saved` |

### performance-history.json の指標

| キー | 取得元 | 更新 |
|---|---|---|
| `genre` / `trial` / `tools[]` / `source` | 投稿時に `record-upload.mjs` が記録（`tools[]` は 30 日以内の重複チェックにも使う） | 投稿時 |
| `stats.views` / `likes` / `comments` | YouTube Data API v3 | `fetch-stats.mjs`（直近 14 日） |
| `instagram.mediaId` | 投稿時に `upload-instagram.mjs` → `record-upload.mjs` が記録。記録がない回は `fetch-stats.mjs` が IG の投稿一覧と JST の投稿日で突き合わせて復元する | 投稿時 / 初回取得時 |
| `instagram.views` / `reach` / `likes` / `comments` / `shares` / `saved` | Instagram Graph API `/{ig-media-id}/insights` | `fetch-stats.mjs`（直近 14 日 + 未取得の回）。最大 48 時間遅れる |

更新だけ手動で行いたいときは `gh workflow run fetch-stats.yml` を使う（動画生成・投稿はしない）。
