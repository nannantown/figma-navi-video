## 要点（正本の要約）

- **1 試行 = 14 日**。判定日 = S + 14k。モードが変わるのは判定日と遅延判定（判定日の朝に判定が出なかったとき、翌朝以降に同じ窓で出す）のときだけ
- **判定指標**: IG = 判定窓の views 中央値と保存数の合計（別々の 2 指標）、YT = 判定窓の views 中央値。**IG と YT は合算しない**。n < 7 なら判定保留
- **閾値**（上から順に当てはめる。初期値・仮置き）: 配信死亡 = IG 中央値 < 10 かつ保存 < 5 / YT 中央値 < 5、切替候補 = IG 中央値 < 50 かつ保存 < 5 / YT 中央値 < 20、それ以外は続行
- **配信死亡モード中**: method の切り口の最適化を止め、構造実験（タイトル個別化・型変更・ジャンル変更）だけを提案する。提案はレポートに書くだけで、当日の原稿・JSON には反映しない。投稿は止めない
- **日次レポート**: `docs/pdca/YYYY-MM-DD.md` の冒頭に「ジャンル試行の状態」節（試行 #・開始日・経過日・判定窓 (n)・判定指標の現在値・モード・次の判定日）を書く
- **このリポの制約**: ジャンル・型・タイトル方針のすべてを変えてよい
